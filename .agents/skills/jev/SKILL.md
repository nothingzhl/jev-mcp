# 使用 Jev 辅助编码调查

使用中文沟通。先确认当前任务需要哪一种判断，以及 MCP 客户端实际列出的工具和输入 schema。Jev 判断不证明执行成功，也不提供修改、部署、重试或其他副作用的权限。

## 选择工具与最少材料

| 目的 | 工具 | 显式提供的最少材料 |
| --- | --- | --- |
| 排序调查材料 | `jev_rank_candidates` | 一个具体调查目标，候选的唯一 id、标题及必要片段 |
| 核对完成/事实声明 | `jev_verify_claims` | 每条声明及其自己的直接证据；计划或命令不代表已执行 |
| 分析失败 | `jev_triage_failure` | 已运行的命令、最少相关错误日志；确实有关时才提供改动摘要 |
| 验证输入和请求计划 | `jev_run_recipe`，`dryRun: true` | 已注册的 recipeId 和对应 input |

调用者负责根据任务权限选择必要材料、剔除凭证和无关私有内容。不把整个仓库、完整历史或全部日志一次上传。内核不会扫描仓库、读取任意路径、执行 Git/测试命令、控制浏览器或修改业务代码。相关规则和边界见仓库的 README.md、examples/ 和 src/recipes/。

同一份输入里的独立问题合并为一次调用：一组候选、各自带证据的多条声明，以及失败的类别/证据判断都已有批量规则。不同失败或不相关任务不要伪装成同一条日志。不自行构造任意模型问题或修改工具 schema。

## 先校验，再按已有授权调用

可先调用 generic 工具验证材料，例如：

```json
{
  "recipeId": "verify-claims",
  "input": {
    "claims": [
      { "id": "check", "claim": "合成测试通过", "evidence": "本次运行：3 passed, 0 failed，退出码 0" }
    ]
  },
  "dryRun": true
}
```

dry run 仅校验和返回请求计划，不联网、不写库，不返回模型判断。三个专用工具默认真实调用；generic 工具的 `dryRun` 默认也是 false。真实调用会把提供的材料发送到 TypeSafe 并产生 API 用量，必须已有覆盖当前任务、材料范围和用量的授权；已有授权不重复询问。无授权时继续可完成的离线工作，不把工具存在视为授权。

凭证只经服务环境 `TYPESAFE_API_KEY` 提供；不要要求用户粘贴 key，不把 key 放进工具参数、聊天、日志或库文件。`.env` 不会自动加载。`doctor` 仅检查 key 是否存在。

## 解读结果与下一步

- 排序保留所有候选及稳定并列顺序。高分表示调查相关性；有问题的代码也可能非常相关。`requiresReview` 不得被隐藏，未入前几名的候选也不是已证伪。
- 排序规则 1.1.0 的 `reviewReason=score_rounding` 表示 Score 仅在本地两位小数舍入假设下兼容，并非官方精度保证。即使 confidence 很高也必须复核，保留 judgment.consistency 及原始分数/概率；不要把此标记覆盖成自动通过。
- 核对证据时保留 `accepted`、`rejected`、`review` 的区别。空证据、insufficient 和低置信必须待复核；accepted 也是基于当前片段的模型判断，需要真实测试/运行证据支撑完成声明。
- 归类保留 `unknown` 和 `requiresReview`。不得把 unknown 猜成具体原因，也不得依据类别自动重试、改配置或回滚。flaky 需要同命令在代码、输入和环境不变时失败后重跑通过的实际记录。
- 记录规则版本、请求模型、实际模型和可用的 request ID。概率不是事实或权限；不要把离线测试、真实 API 可达、模型质量评测混为一谈。
- 上游/鉴权/超时/存储错误与低置信判断不同。报告工具返回的安全错误码，不复述 SDK 原始 body。SDK 是唯一重试层；调用者不要自动重试，以免重复计费。STORAGE 可能发生在推理完成后，不能推断未产生用量。

## 工具不可用时降级

MCP 未配置或不可发现时，说明当前能力缺口。若仓库和 Node 24 可用，在仓库目录用 `node dist/cli.js recipes`、`node dist/cli.js doctor`；缺少构建时按 README 安装并构建。用 `node dist/cli.js run <recipe> --input <显式文件> --dry-run` 验证输入；该输出含原始材料，保存或分享前检查。经已有授权的真实 CLI 调用才去掉 --dry-run。

无 key、上游不可用或任务未授权真实调用时，依据已收集的证据继续人工调查/本地测试，明确标注无法得到 Jev 判断；不要伪造分数或用合成输出冒充真实推理。不要自动安装全局 skill、修改用户 MCP 配置，或把服务暴露为 HTTP。

评测器使用说明在 docs/evaluation.md。固定合成预测仅测试评测代码；需要真实质量数据时应另获评测授权、使用外部标注集，并显式选择 live 与样本/请求上限。
